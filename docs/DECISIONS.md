# Decisions log

One line per decision: date, milestone, what we decided, and why. Newest last.

- **2026-10-16 · M1** · Native Windows dev (not WSL). The Makefile's recipes are plain commands that run under cmd.exe, bash and zsh, and anything fancier goes in `scripts/*.py`. *Why:* the dev machine is native Windows, and `make` there uses cmd.exe because `sh` isn't on the PATH.
- **2026-10-16 · M1** · FalkorDB image pinned by digest `falkordb/falkordb@sha256:b0bdcac2…ae7a` (graph module 42201). Compose reuses the container name `falkordb` and keeps data on the `domino_falkordb_data` volume at `/var/lib/falkordb/data`. *Why:* the spike passed on exactly this build.
- **2026-10-16 · M1** · We keep the image defaults `TIMEOUT 1000` and `RESULTSET_SIZE 10000`. *Why:* they protect the public demo, and every engine query is small. `run_query` will pass an explicit per-query timeout and raise on a result of exactly RESULTSET_SIZE rows, because truncation is otherwise silent (SPIKE #14).
- **2026-10-16 · M1** · MCP SDK 2.x: `MCPServer` (formerly `FastMCP`) is mounted in the FastAPI app at `/mcp`, with its session manager started in the lifespan. No separate process is needed (SPIKE #16). We'll set the deploy hostname in `allowed_hosts`, because the SDK rejects foreign `Host` headers with 421.
- **2026-10-16 · M1** · `algo.betweenness` is not used for port chokepoints (P1). We'll use `algo.maxFlow` knockouts or exact betweenness in Python instead. *Why:* its scores are sample estimates that don't match hand-computed values, and unseeded calls vary between runs (SPIKE #4).
- **2026-10-16 · M1** · We don't re-apply the schema after `GRAPH.COPY`. *Why:* indexes, the full-text index and the unique constraint are all copied (SPIKE #5).
- **2026-10-16 · M1** · Q-EXECUTE stays a single write query, with the preflight read before it. *Why:* a constraint violation rolls back the whole query, including nodes, edges and SETs (SPIKE #11).
- **2026-10-16 · M1 review** · **Preflight before execution (M5) checks every reference, not just the supply edge.** For each PO it confirms that the site, plant and component match, that the allocation list is not empty, that every `allocations[].order_id` matches an Order, and that the PO id doesn't exist yet. It must return exactly the planned counts. Preflight and the write run under the same per-world lock, together with the `world_version` check. *Why:* a `MATCH` that finds nothing raises no error, so rollback doesn't help. The PLAN §8 draft would silently drop `PROTECTS` edges for missing order ids. V9 would only catch that after the write had committed.
- **2026-10-16 · M1 review** · **Min-cut correctness check (M4): the total capacity of the cut edges must equal the max flow.** This replaces the PLAN §7.6 idea of raising one cut edge's capacity and checking that the flow increases. The search for reachable nodes runs on the full projected network kept in Python. That network includes the site-capacity edges from node splitting and zero-flow edges. Edges FalkorDB left out count as flow 0, and flows are cast to int. The search starts from all sources. *Why:* if there's a second, equally tight cut, raising one cut edge's capacity doesn't change the flow, so that test can fail on correct code. FalkorDB only returns edges that carry flow (SPIKE #2).
- **2026-10-16 · M1 review** · **`run_query` refuses results it can't prove are complete.** A result with exactly `RESULTSET_SIZE` rows (10000) counts as possibly truncated. The query is either paged through with `SKIP`/`LIMIT` or rejected with an error, and the result is never used as it is. *Why:* FalkorDB truncates without raising (SPIKE #14), and a cut-off result would quietly corrupt capacity and shortage numbers.
- **2026-10-16 · M2** · **The generator is pure and split into per-phase RNG streams** (`random.Random(f"{seed}:{phase}")` for customers, demand, orders and fill). *Why:* the same seed always gives the same world (checked by a sha256 fingerprint), and changing one phase, e.g. adding a filler chain, doesn't reshuffle the orders.
- **2026-10-16 · M2** · **Motif design numbers live as plain data tables in `seed/motifs.py`** (sites, FEEDS, SUPPLIES, CAN_SUPPLY, stock, fixed demand, the incident to declare). *Why:* each number has exactly one home and can be explained to judges. Engines never read these tables; they read the graph.
- **2026-10-16 · M2** · **Filler supply is sized from the generated orders**, so stock plus a steady supply rate covers every order by its need day (with a 5% margin). The generator refuses to build a world that fails this check (`pristine_cover_gaps`). *Why:* the pristine world must have 0 projected-late orders (CLAUDE.md rule 6), so the healthy baseline can't be an accident of the random draw.
- **2026-10-16 · M2** · **Tier-1 lines buy inputs at their full line rate.** For example, PowerCell's FEEDS total 3,600 cells/wk, which is 900 packs × 4. That is its 700/wk Kestrel contract plus the 200/wk "extra" alternate. ElectroHub's Hanriver FEEDS edge is cap 3,600 with 1,200 used for other buyers. That leaves the 2,400 cells/wk of headroom from §5.6, so Hanriver is genuinely contested between PowerCell and ElectroHub. *Why:* it keeps the §5.6 numbers and makes the material balance self-consistent.
- **2026-10-16 · M2** · **Scarce Silicon (§5.7) is deferred.** K7 is an ordinary filler part (tier-2 die fab → tier-1 OSAT) for now. *Why:* crunch plan (§0.1) cut order. The motif can be added later as one more data table.
- **2026-10-16 · M2** · **The generator never places a filler site in the Chao Phraya Basin**, and `validate()` checks that VoltCell is the only site there. *Why:* the tier-1 view = 0 result must come from the real graph structure. A stray filler site in the zone would quietly change the demo beat.
- **2026-10-16 · M2** · **Extra id indexes** on `Place`, `Supplier`, `Product` and `Customer`, besides the §5.9 set. *Why:* one loader query can attach `LOCATED_IN`/`SHIPS_VIA`/`DELIVERS_TO` to any location through `:Place`, and the indexes cost nothing at this size.
- **2026-10-16 · M2** · **Seed loading is one named query per label or relationship type** (`queries/seed/*.cypher`, batched `UNWIND` of 500 rows). Each query returns `created`, and the loader fails if that differs from the batch size. After loading, the counts read back from the graph must equal the generated world, and `checks/duplicate_ids` must return no rows. *Why:* a `MATCH` with a missing endpoint drops the row without an error.
- **2026-10-16 · M2** · **`ALLOWS_ALTERNATE` uses the property `for_component`** instead of `for`, and `CAN_SUPPLY` also carries `air_transit_days` and `air_surcharge_cents`. *Why:* this avoids a keyword-looking property name, and air freight (the Meridian rescue) needs a price and a speed.
- **2026-10-16 · M2** · **`run_query` passes a timeout on every call** (5 s for reads, 30 s for writes) and raises `ResultTruncatedError` when a result reaches `RESULTSET_SIZE`, which it reads from `GRAPH.CONFIG`. Multi-statement DDL goes through `run_script`, which logs each statement as `<name>#<i>`. `GRAPH.CONSTRAINT CREATE` is a Redis command, so it stays in `schema.py`.
- **2026-10-17 · M3** · **Shortage availability uses exact fractions** (`fractions.Fraction`). Arrivals are whole units taken from the exact cumulative inflow, `floor(cum(t+1)) - floor(cum(t))`. *Why:* the projection is deterministic, and the tiny-world numbers can be checked by hand without float drift.
- **2026-10-17 · M3** · **Timing model.** A disrupted site's output drops on day 0. A site whose inputs drop feels it `input_buffer_days` later, and buffers add up tier by tier. Each supply edge delivers the reduced rate from `onset + transit_days` and the full rate again from `restore + transit_days`, where `restore` is the latest `disrupted_until` among the reduced sources. *Why:* this is the §7.5 pipeline rule, extended to multi-tier chains. It is a simplification: each site gets one onset and one restore day, and refilling the buffer isn't modelled.
- **2026-10-17 · M3** · **Inputs are weighted by `used_wk`, falling back to `cap_wk` when nothing flows today.** Interchangeable sources of the same component are combined as a used-weighted share. Complementary components take the minimum share (CLAUDE.md rule 7).
- **2026-10-17 · M3** · **EDF without head-of-line blocking.** Each day, pending orders are checked in (need_day, strategic first, id) order. An order that can't get *every* part waits and consumes nothing, and a later order that can be served still goes ahead. *Why:* this is the §7.5 pseudo-code. Note that a big strategic order can sit short while smaller orders are served. Protecting it is the allocator's job (M5), not the do-nothing projection's.
- **2026-10-17 · M3** · **Orders still short at the horizon are "late beyond horizon"**, with `late_days = horizon + 1 - need_day` reported as a lower bound. Their penalty is labelled "at least" in the CLI.
- **2026-10-17 · M3** · **"Exposed" is computed twice and the two must agree.** The exposure engine finds exposed orders by graph traversal (Q-EXPOSURE). The shortage engine finds them as orders that need a part whose supply edge runs below full rate. A test checks that both give the same set on Monsoon.
- **2026-10-17 · M3** · **Q-DECLARE also bumps `Meta.world_version`, in the same atomic write.** The caller checks that `sites_affected` equals the number of sites it sent. Unknown entity ids return `unknown_entity` before anything is written. `make cli` declares the incident on `world:cli:<scenario>`, a fresh GRAPH.COPY of pristine, so `world:live` is never touched and the result can be inspected in FalkorDB Browser.
- **2026-10-17 · M3** · **EXPOSES edges are not written yet.** *Why:* nothing reads them before the agent (M6), and they need the shortage numbers (`late_days`, `shortfall`). They will be added with the MCP tool.
- **2026-10-17 · M4** · **Capacity networks are solved per (component, plant), in units of that component per week.** Node splitting gives each site `<site>:in -> <site>:out` with `floor(capacity_wk × factor ÷ BOM ratio)`. A FEEDS edge gets `cap_wk ÷ ratio`, and the ratio is the product of `MADE_FROM.qty` along the BOM path. The edge into the plant is the site's contract `used_wk` plus its approved `spare_wk` (potential). Parallel edges are merged so FalkorDB's flows map back to a unique edge. One scratch graph per network carries two capacity properties: `cap` (today's factors) and `cap_nominal` (all healthy). That way true vs healthy capacity is two `algo.maxFlow` calls on one graph. The graph is dropped in `finally`.
- **2026-10-17 · M4** · **The min cut is checked on every solve: total cut capacity must equal the max flow, or the engine raises.** This is the check from the M1 review. Edges FalkorDB leaves out count as flow 0. A test covers a network where every edge is saturated but only one edge is the cut.
- **2026-10-17 · M4** · **Naive capacity = Σ over tier-1 sites of (contract + approved spare) into this plant.** That gives BAT-4S → Bac Ninh 1,900 (matches §5.6) and BAT-6S → Penang 980. §5.6's "≈1,450" for 6S added BatteryMax's whole 800/wk line capacity, which isn't a per-plant figure. True capacity matches the design (700 and 650).
- **2026-10-17 · M4** · **Alternatives: rejection only when remaining clean capacity is 0** (AmpereOne). An exposed candidate with healthy inputs is accepted with a warning and a "reduced" flag (PowerCell extra: site clean 400/wk of 900). Candidates include same-family look-alikes built from the same input (DSP-14-HB), so the BOM check rejects them explicitly as `incompatible`. When the extra volume comes from a site that already holds a contract (PowerCell), the shared contract volume is reported. Splitting that site's clean capacity is left to the joint allocator (M5).
- **2026-10-17 · M4** · **Max-flow is single-commodity.** If a site needs complementary inputs, the engine warns that its capacity is an upper bound. None in the demo world does.
- **2026-10-17 · M5** · **Greedy allocator with rollback.** Orders are processed by (need_day, strategic first, id). For each part it is short of, an order takes the largest quantity each source can deliver by its need day, found by binary search over monotone checks: the rate needed at every checkpoint, spare, clean capacity, upstream room and budget. An order that can't be fully covered is rolled back, so "protected (projected)" never means half-covered (V7). Naive (S1) and graph-aware (S2–S4) modes run the same code. Naive mode sees AmpereOne and skips upstream bookkeeping.
- **2026-10-17 · M5** · **One upstream attribution rule for the allocator, the sandbox and V8** (`engines/upstream.py`). Existing contracts keep priority. New PO demand goes to healthy feeders first, each up to its FEEDS headroom. Joint rationing then gives every PO the same proportional share of an overloaded feeder. Only one tier of feeders is modelled.
- **2026-10-17 · M5** · **PROTECTS quantities are earmarked for their order in the shortage projection.** PO units fill their own allocations first, and only leftover units (MOQ padding) join the plant's pool. *Why:* with pooled stock, an older unprotected order (Penang's SO-1031) ate the units bought for protected orders. The projection then disagreed with the plan's own promise. Now a protected order shows as late only if its PO really under-delivers (the baseline's AmpereOne).
- **2026-10-17 · M5** · **Q-EXECUTE checks the plan's world_version inside the write and bumps it there**, so a world change between the checks and the write makes the write match nothing. Preflight also checks that each PO's rate fits the CAN_SUPPLY edge's free spare (`spare_wk − reserved_wk`). The negative tests for V1–V7 therefore write straight to the graph, bypassing the preflight.
- **2026-10-17 · M5** · **Net benefit = penalties avoided − spend.** Revenue protected is shown separately, because a late order is usually shipped late, not lost. The CLI prints a negative net when that's the result (Panel Fire: −$44,500).
- **2026-10-17 · M5** · **Known limitation:** the allocator buys the *full* quantity of every late order's short part, not just the deficit the existing pool leaves. That over-buys when the outage is short (Panel Fire). The fix is deficit-based sizing with V7 counting pool availability. Deferred.
- **2026-10-17 · M5** · Recovery budget defaults to **$250,000** per decision (`allocators/strategies.py`).
- **2026-10-17 · M6** · **The agent reaches its tools over MCP through `mcp.client.Client`.** In the headless demo, the API and the tests it connects in-process to the same `MCPServer` object that is mounted at `/mcp`. External clients (Claude Desktop/Code) use streamable HTTP. *Why:* the protocol path is the same either way, and the agent doesn't depend on its own HTTP server being up. A check confirmed all 15 tools (plus `health`) are served over HTTP.
- **2026-10-17 · M6** · **Run context lives server-side; `run_id` is injected by the loop and stripped from the schema the model sees.** It holds result refs (R-01…), evidence (E1…), plans, the pending decision and the ids seen. External clients without a run id share an "external" context on the live world.
- **2026-10-17 · M6** · **Catalogue:** resolve_entities, declare_incident, get_entity_context, recall_history, trace_exposure, explain_shared_dependencies, project_shortages, compute_true_capacity, find_alternatives, simulate_strategies, flag_orders_at_risk, submit_plan_for_approval, verify_execution, record_lessons, submit_incident_report. `generate_strategies` is folded into `simulate_strategies`, because the plans are only meaningful after their sandbox run. `execute_plan` is not a tool. Deferred: `hold_inventory`, plus the P1 tools `request_clarification`, `draft_customer_notices` and `find_routes`.
- **2026-10-17 · M6** · **Every id argument is resolved before any engine runs.** An unknown id raises MCP `ToolError` (`is_error: true`) with difflib "did you mean" suggestions, so the agent can recover.
- **2026-10-17 · M6** · **API settings come from the claude-api skill:** `claude-opus-5-5`, `thinking: adaptive`, explicit `output_config.effort` (`DOMINO_EFFORT`), no `tool_choice` (forced choice is a 400), streaming via `client.beta.messages.stream`, `cache_control` on the system block, and `fallbacks: "default"` with beta `server-side-fallback-2026-07-01`. The loop handles `refusal`, `max_tokens` and `pause_turn`. Tools set `eager_input_streaming`, and non-dict inputs are answered with `INVALID_JSON`. History is append-only. A human's approve/reject note is added to the pending, not-yet-sent tool-result turn.
- **2026-10-17 · M6** · **Structured report validation.** Every cited evidence id must have been returned in this run. A `depends_on`/`exposed`/`rejected` claim's entities must lie on its cited paths. Every `metric_ref` (e.g. `R-04.totals.projected_late`) must resolve in this run's results. The entity guard rejects any site, supplier, order or plant id in the narrative that no tool returned. Not yet checked: units, and the world version of a metric.
- **2026-10-17 · M6** · **A scripted stand-in model (`agent/scripted.py`)** drives the real loop, MCP tools, approval and report validation offline and at $0, for tests and `make demo-headless DRY_RUN=1`. It is not the agent, and the real-model run has not been tried yet (it costs API credit).
- **2026-10-17 · M6** · HTTP runs share `world:live` for now; per-session worlds are P1. A double approve click gets 409. The FastAPI lifespan starts the MCP session manager only once per process, because a second start raises in the SDK (that only happens in tests).
- **2026-10-17 · M6** · `make demo-headless DRY_RUN=1` writes memory to `memory:dryrun`, never to `memory`. *Why:* a scripted lesson in the real memory graph would later be "remembered" by a real run. The one dry-run lesson written before this fix was deleted.
- **2026-10-17 · M7** · **One image, one origin.** A multi-stage `Dockerfile` (pnpm build, then `uv sync --frozen --no-dev`) produces an image where FastAPI serves the built frontend at `/` next to `/api` and `/mcp`, so there is no CORS. Caddy proxies with `flush_interval -1`. A local run of the production stack showed SSE events arriving live through Caddy while the stream stayed open.
- **2026-10-17 · M7** · **FalkorDB has no published ports in production.** Only the app reaches it. On start the container runs `domino.seed.ensure`, which builds `world:pristine` / `world:live` only if missing, so restarts keep the demo state and the memory graph.
- **2026-10-17 · M7** · **Public-demo protections were brought forward from M11.** Real agent runs are capped per visitor per hour (`LIVE_RUNS_PER_HOUR_PER_IP`) and globally per day (`LIVE_RUNS_PER_DAY`). uvicorn runs with `--proxy-headers`, so the cap sees the real client IP behind Caddy. When `MCP_API_KEY` is set, `/mcp` needs `Authorization: Bearer <key>` or `X-API-Key`. The MCP Host check allows `DOMINO_PUBLIC_HOST` (otherwise 421). *Why:* a public URL must not be able to spend the API credit or mutate the live world freely.
