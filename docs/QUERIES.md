## agent

### agent/all_ids

Every id in the world, for "did you mean" suggestions on unknown ids. Small world; capped.

Used by: `backend/domino/agent/tools.py`

```cypher
MATCH (n) WHERE n.id IS NOT NULL
RETURN n.id AS id
LIMIT 5000
```

### agent/entity_context

An entity's properties and its 1-hop neighbourhood (get_entity_context).

Used by: `backend/domino/agent/tools.py`

```cypher
MATCH (n {id: $entity_id})
OPTIONAL MATCH (n)-[r]-(m)
RETURN properties(n) AS props, labels(n) AS labels, type(r) AS rel, startNode(r) = n AS outgoing,
       m.id AS other, labels(m) AS other_labels, properties(r) AS rel_props
LIMIT 60
```

### agent/resolve_places

## alternatives

### alternatives/acceptable

Products at the plant that need $component_id, and the substitutes each one approves (ALLOWS_ALTERNATE).

Used by: `backend/domino/engines/alternatives.py`

```cypher
MATCH (pl:Plant {id: $plant_id})-[b:BUILDS]->(p:Product)-[req:REQUIRES]->(k:Component {id: $component_id})
OPTIONAL MATCH (p)-[aa:ALLOWS_ALTERNATE]->(alt:Component)
WHERE aa.for_component = $component_id
RETURN p.id AS product, collect(DISTINCT alt.id) AS alternates
ORDER BY product
```

### alternatives/candidates

Q-ALTERNATIVES: approved-vendor-list sources into the plant, with the taint check. Any disrupted site 1-4 FEEDS hops upstream is returned as an evidence path. Exposure is a warning, not a rejection. nodes(null) after an OPTIONAL MATCH miss is null and collect() drops it, so clean sites get [].

Used by: `backend/domino/engines/alternatives.py`

```cypher
MATCH (alt:Site)-[cs:CAN_SUPPLY]->(pl:Plant {id: $plant_id})
WHERE cs.component_id IN $component_ids
OPTIONAL MATCH taint = (bad:Site)-[:FEEDS*1..4]->(alt)
WHERE bad.status = 'disrupted'
WITH alt, cs, collect(DISTINCT [n IN nodes(taint) | n.id]) AS tainted_paths
RETURN alt.id AS site, cs.component_id AS component, cs.spare_wk AS spare_wk, coalesce(cs.reserved_wk, 0) AS reserved_wk,
       cs.unit_price_cents AS price_cents, cs.lead_days AS lead_days, cs.transit_days AS transit_days,
       cs.air_transit_days AS air_transit_days, cs.air_surcharge_cents AS air_surcharge_cents,
       cs.moq AS moq, cs.qualified AS qualified, cs.requal_days AS requal_days,
       alt.status AS site_status, tainted_paths
ORDER BY price_cents, site
```

### alternatives/lookalikes

Same-family components built from the same input as $component_id (e.g. DSP-14-HB for DSP-14). They are listed as candidates so the BOM check can reject them explicitly.

Used by: `backend/domino/engines/alternatives.py`

```cypher
MATCH (k:Component {id: $component_id})-[m1:MADE_FROM]->(x:Component)<-[m2:MADE_FROM]-(c:Component)
WHERE c.id <> k.id AND c.family = k.family
RETURN DISTINCT c.id AS component
ORDER BY component
```

## decision

### decision/approve

Approve a proposed decision. Only matches if the plan the human saw (plan_hash) is the one on record.

Used by: `backend/domino/engines/executor.py`

```cypher
MATCH (d:Decision {id: $decision_id})
WHERE d.status = 'proposed' AND d.plan_hash = $plan_hash
SET d.status = 'approved', d.approved_by = $approved_by
RETURN d.id AS decision, d.status AS status
```

### decision/create

Record a proposed plan as a Decision bound to its plan_hash and the world_version it was simulated on. MERGE keeps a re-proposal of the same decision id from creating a second node; the caller compares plan_hash.

Used by: `backend/domino/engines/executor.py`

```cypher
MATCH (inc:Incident {id: $incident_id})
MERGE (d:Decision {id: $decision_id})
ON CREATE SET d.strategy = $strategy, d.status = 'proposed', d.plan_hash = $plan_hash,
              d.world_version = $world_version, d.budget_cents = $budget_cents, d.rationale = $rationale
MERGE (inc)-[r:RESOLVED_BY]->(d)
RETURN d.id AS decision, d.status AS status, d.plan_hash AS plan_hash
```

### decision/get

Decision state plus the current world_version, for the executor's pre-write checks. feedback is set only when a human rejected the decision.

Used by: `backend/domino/agent/tools.py`, `backend/domino/api/world.py`, `backend/domino/engines/delivery.py`, `backend/domino/engines/executor.py`, `backend/domino/engines/sandbox.py`

```cypher
MATCH (m:Meta {id: 'META'})
OPTIONAL MATCH (d:Decision {id: $decision_id})
RETURN d.id AS decision, d.status AS status, d.plan_hash AS plan_hash, d.world_version AS decision_world_version,
       d.budget_cents AS budget_cents, d.feedback AS feedback, m.world_version AS world_version
```

### decision/reject

A human rejected a proposed decision: record who and why, so the graph shows the decision was refused. Only a proposed decision can be rejected; an approved or executed one is left as it is.

Used by: `backend/domino/engines/executor.py`

```cypher
MATCH (d:Decision {id: $decision_id})
WHERE d.status = 'proposed'
SET d.status = 'rejected', d.rejected_by = $rejected_by, d.feedback = $feedback
RETURN d.id AS decision, d.status AS status
```

## delivery

### delivery/committed

Committed purchase orders waiting for delivery, with what the outcome model needs: the source edge's approved spare and how much of it is now reserved, and the reliability of the company that runs the site.

Used by: `backend/domino/engines/delivery.py`

```cypher
MATCH (d:Decision)-[cr:CREATED]->(po:PurchaseOrder)-[fs:FROM_SITE]->(s:Site)
MATCH (po)-[fc:FOR_COMPONENT]->(k:Component)
MATCH (po)-[dt:DELIVERS_TO]->(pl:Plant)
WHERE po.status = 'committed'
MATCH (s)-[cs:CAN_SUPPLY]->(pl)
WHERE cs.component_id = k.id
OPTIONAL MATCH (sup:Supplier)-[op:OPERATES]->(s)
RETURN po.id AS po_id, d.id AS decision_id, s.id AS site, s.name AS site_name, sup.id AS supplier,
       sup.reliability AS reliability, k.id AS component, pl.id AS plant, po.rate_wk AS rate_wk, po.qty AS qty,
       po.mode AS mode, po.first_arrival_day AS first_arrival_day, cs.spare_wk AS spare_wk,
       coalesce(cs.reserved_wk, 0) AS reserved_wk
ORDER BY po_id
```

### delivery/outcomes

Delivered purchase orders and how they went (Shipments view, get_delivery_outcomes), with the orders each one protected and their final status.

Used by: `backend/domino/engines/delivery.py`

```cypher
MATCH (po:PurchaseOrder)-[fs:FROM_SITE]->(s:Site)
WHERE po.status IN ['received', 'delayed']
MATCH (po)-[fc:FOR_COMPONENT]->(k:Component)
MATCH (po)-[dt:DELIVERS_TO]->(pl:Plant)
OPTIONAL MATCH (po)-[pr:PROTECTS]->(o:Order)
RETURN po.id AS po_id, s.id AS site, s.name AS site_name, k.id AS component, pl.id AS plant, po.mode AS mode,
       po.qty AS qty, po.status AS status, po.first_arrival_day AS planned_day, po.arrived_day AS arrived_day,
       po.days_late AS days_late, po.received_day AS received_day,
       collect({order_id: o.id, qty: pr.qty, need_day: o.need_day, status: o.status, delivered_day: o.delivered_day,
                late_days: o.late_days}) AS orders
ORDER BY po_id
```

### delivery/write

Q-DELIVER: one atomic write after the simulated clock reaches delivery. Matches only if the world is still at the version the outcomes were computed on; bumps world_version and records the simulated day. Each PO becomes 'received' (on time) or 'delayed' (arrived days_late days after plan) and frees the spare it reserved; each order it protected becomes 'fulfilled', 'fulfilled_late' or 'unfulfilled'. The caller compares pos_updated / orders_updated with what it sent.

Used by: `backend/domino/engines/delivery.py`

```cypher
MATCH (m:Meta {id: 'META'})
WHERE m.world_version = $world_version
SET m.world_version = m.world_version + 1, m.day = $day
WITH m
UNWIND $pos AS x
MATCH (p:PurchaseOrder {id: x.id})
WHERE p.status = 'committed'
MATCH (s:Site {id: x.site})-[cs:CAN_SUPPLY]->(pl:Plant {id: x.plant})
WHERE cs.component_id = x.component
SET p.status = x.status, p.days_late = x.days_late, p.arrived_day = x.arrived_day,
    p.received_day = x.received_day,
    cs.reserved_wk = CASE WHEN coalesce(cs.reserved_wk, 0) > p.rate_wk THEN cs.reserved_wk - p.rate_wk ELSE 0 END
WITH m, count(DISTINCT p) AS pos_updated
UNWIND $orders AS y
MATCH (o:Order {id: y.id})
WHERE o.status = 'protected_projected'
SET o.status = y.status, o.delivered_day = y.delivered_day, o.late_days = y.late_days
WITH m, pos_updated, count(DISTINCT o) AS orders_updated
CREATE (act:Action {id: $action_id, type: 'deliver', actor: 'simulator', day: $day, payload_json: $payload_json})
RETURN pos_updated, orders_updated, m.world_version AS world_version, m.day AS day
```

## execute

### execute/preflight

Q-EXECUTE-PREFLIGHT (read). One row per planned PO. The executor requires: N rows for N POs, the CAN_SUPPLY edge and component exist, the PO id is new, the PO has allocations, every allocation's order exists, and the edge still has free spare for the rate.

Used by: `backend/domino/engines/executor.py`

```cypher
UNWIND $pos AS po
OPTIONAL MATCH (s:Site {id: po.site_id})-[cs:CAN_SUPPLY]->(pl:Plant {id: po.plant_id})
WHERE cs.component_id = po.component_id
OPTIONAL MATCH (k:Component {id: po.component_id})
OPTIONAL MATCH (existing:PurchaseOrder {id: po.id})
OPTIONAL MATCH (o:Order) WHERE o.id IN po.order_ids
RETURN po.id AS po_id, count(DISTINCT cs) AS edges, count(DISTINCT k) AS components,
       count(DISTINCT existing) AS existing, count(DISTINCT o) AS orders_found, size(po.order_ids) AS orders_planned,
       size(po.allocations) AS allocations, max(cs.spare_wk - coalesce(cs.reserved_wk, 0)) AS free_wk, po.rate_wk AS rate_wk
ORDER BY po_id
```

### execute/write

Q-EXECUTE: one atomic write. Matches only if the decision is approved with this plan_hash and the world is still at the version the plan was simulated on; bumps world_version; creates every PO with its links and PROTECTS allocations; marks orders protected (projected); logs an Action. The unique constraint on PurchaseOrder.id rolls the whole query back on a duplicate. The executor compares pos_created / protects_created with the plan (invariant V9).

Used by: `backend/domino/engines/executor.py`

```cypher
MATCH (d:Decision {id: $decision_id})
WHERE d.status = 'approved' AND d.plan_hash = $plan_hash
MATCH (m:Meta {id: 'META'})
WHERE m.world_version = $world_version
SET m.world_version = m.world_version + 1
WITH d, m
UNWIND $pos AS po
MATCH (s:Site {id: po.site_id})-[cs:CAN_SUPPLY]->(pl:Plant {id: po.plant_id})
WHERE cs.component_id = po.component_id
MATCH (k:Component {id: po.component_id})
CREATE (p:PurchaseOrder {id: po.id, qty: po.qty, rate_wk: po.rate_wk, unit_price_cents: po.unit_price_cents,
                         mode: po.mode, first_arrival_day: po.first_arrival_day, status: 'committed',
                         created_by: 'domino'})
CREATE (d)-[:CREATED]->(p), (p)-[:FROM_SITE]->(s), (p)-[:FOR_COMPONENT]->(k), (p)-[:DELIVERS_TO]->(pl)
SET cs.reserved_wk = coalesce(cs.reserved_wk, 0) + po.rate_wk
WITH d, m, p, po
UNWIND po.allocations AS a
MATCH (o:Order {id: a.order_id})
CREATE (p)-[pr:PROTECTS {qty: a.qty, arrival_day: a.arrival_day}]->(o)
SET o.status = 'protected_projected'
WITH d, m, count(DISTINCT p) AS pos_created, count(pr) AS protects_created, collect(DISTINCT o.id) AS orders
SET d.status = 'executed', d.executed_day = $day
CREATE (d)-[:LOGGED]->(act:Action {id: $action_id, type: 'execute', actor: 'executor', day: $day,
                                    payload_json: $payload_json})
RETURN d.id AS decision, pos_created, protects_created, orders, m.world_version AS world_version
```

## exposure

### exposure/exposure

Q-EXPOSURE: multi-tier exposure of unknown depth, with the evidence path for every hit. *0..4 includes the affected site itself when it is a tier-1 supplier. One row per (chain, tier-1, component, product, plant); orders are collected per row.

Used by: `backend/domino/engines/exposure.py`

```cypher
MATCH (inc:Incident {id: $incident_id})-[a:AFFECTS]->(d:Site)
MATCH chain = (d)-[:FEEDS*0..4]->(t1:Site)
MATCH (t1)-[sup:SUPPLIES]->(pl:Plant)-[b:BUILDS]->(prod:Product)-[req:REQUIRES]->(k:Component)
WHERE k.id = sup.component_id
MATCH (o:Order)-[fp:FOR_PRODUCT]->(prod)
MATCH (o)-[fa:FULFILLED_AT]->(pl)
WHERE o.status = 'open' AND o.need_day <= $horizon
RETURN d.id AS origin, [n IN nodes(chain) | n.id] AS supply_path, length(chain) AS upstream_hops,
       t1.id AS tier1, k.id AS component, prod.id AS product, pl.id AS plant,
       collect(o.id) AS orders, sum(o.value_cents) AS value_cents
ORDER BY origin, tier1, plant, component, product, upstream_hops
```

### exposure/shared_upstream

Q-SHARED: affected upstream sites that feed two or more tier-1 sites (active or alternate). This is the proof that "independent" backups share a hidden dependency.

Used by: `backend/domino/engines/exposure.py`

```cypher
MATCH (inc:Incident {id: $incident_id})-[a:AFFECTS]->(d:Site)
MATCH (d)-[f:FEEDS*1..4]->(t1:Site)-[e:SUPPLIES|CAN_SUPPLY]->(pl:Plant)
WITH d, collect(DISTINCT t1.id) AS dependents
WHERE size(dependents) >= 2
MATCH (sup:Supplier)-[op:OPERATES]->(d)
RETURN d.id AS shared_upstream, sup.name AS operator, dependents, size(dependents) AS fan_out
ORDER BY shared_upstream
```

### exposure/tier1_view

Q-TIER1-VIEW: what a tier-1-only system sees. Affected sites that themselves supply a plant.

Used by: `backend/domino/engines/exposure.py`

```cypher
MATCH (inc:Incident {id: $incident_id})-[a:AFFECTS]->(s:Site)-[sup:SUPPLIES]->(pl:Plant)
RETURN count(DISTINCT s) AS directly_affected_tier1, collect(DISTINCT s.id) AS sites
```

### flow/load_edges

Scratch flow graph edges, in units of the target component per week. cap = with today's capacity factors; cap_nominal = every site healthy.

Used by: `backend/domino/engines/capacity.py`

```cypher
UNWIND $rows AS r
MATCH (a:F {id: r.src})

       feeds_out, contracts, contracts > 0 AS direct_contract
ORDER BY site
```
